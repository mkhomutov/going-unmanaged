## Appendix M — Field Questions

Parts I–VI teach the language; [Appendix F](F-rosetta-cookbook.md#appendix-f--the-rosetta-cookbook) answers the question that arrives with a C# name already attached, and [Chapter 25](25-findings-from-practice.md#chapter-25--gotchas-the-findings-log) the one that arrives as something wrong on the screen. This appendix is for the third kind: the question asked mid-task that maps to no C# API and announced itself with no symptom — *does the standard promise this order*, *what does this cast actually do*, *is this the same thing as that*. It is asked once, answered once, and the answer is filed here so that the next person, or the same person a month later, finds it by searching instead of by asking again.

An entry is a question and its answer, in the Findings' voice: the question stated plainly as the heading, the answer in plain terms, the listing that proves it, the C# contrast, and the habit to carry away. Every listing lives as code in `exercises/questions/`, is included on this page rather than copied to it, and is built and run under the canonical flags by `scripts/build_all.sh` on every push — its `main()` asserts what the entry claims, so an answer that stops being true stops the build. Entry numbers are stable: entries append at the end with the next free number and are never renumbered, so a note that says "Q3" stays right.

Questions arrive through the repository's *Question* issue form; where each one lands is decided by rule, not by the asker, and the rule is in CONTRIBUTING.md.

> [!TIP]
> **Key principle:** "I write the answer down where the next question will find it, with the listing that proves it — an answer that lives in a chat is asked again."
